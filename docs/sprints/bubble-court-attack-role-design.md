# 同一攻击：发送者和接收者的界面设计

交付：独立设计页 `http://127.0.0.1:8780/bubble-court/duel/design/`。未接入实际对战，未提交、未部署。

## 需求与 AC

用户希望区分相同弹出动画的发送者与接收者。/sm、/arch、/ui预审和/rev复查通过。

- 同一次攻击RILEY→JORDAN，两栏分别注明你=RILEY（发送）、你=JORDAN（接收），不是两个不同攻击。
- 发起方用青绿色YOUR ATTACK、上行箭头和较小庆祝卡；强调目标、发出数量和被抵消数量。
- 接收方用橙色INCOMING、警告符号、大倒数和下行箭头；强调来源、剩余干扰和可执行的消除抵消办法。
- 发送方示例能量100→0，接收方保持64，避免误以为被攻击也会扣自己的能量。
- 同一次攻击的预告/动作/命中三个关键帧可切换，模拟抵消1个/全部/重置4个。
- 实际数量一致；全抵消时不画落球，接收方BLOCK，发送方‘被对手全部化解’；切回预告也显示已化解。
- 固定棋盘、叠加效果、可收起；不新增暂停、不修改DEMO01规则。

## 实现与验证

只新增 `public/bubble-court/duel/design/`，复用现有免费双手扣篮SVG。`roles.mjs`为纯展示数据，`app.mjs`用单一模拟攻击驱动两视角，飞行箭头按目标缩略棋盘/本方棋盘真实DOM位置计算；无额外RAF或联网请求。

4项展示逻辑测试先红后绿：0/1/4剩余、阶段文案、同一攻击身份、能量差异、全部抵消后回看阶段。浏览器桌面并排、390px手机上下排列，无水平溢出；全部抵消后SVG落球数0、接收方64能量不变；以phone-screen相对坐标断言切阶段与收起不改变棋盘/底栏尺寸。页面滚动会改变viewport坐标，已按手机框内坐标排除滚动影响；控制台无错误。
