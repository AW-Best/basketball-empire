# 居中受击演出与局部慢放

用户要求：接收方动画居中、其他行为暂停；下扣那一下放慢。只在本地修改，不提交、不部署。

## AC 与方案

/sm、/arch、/ui预审，/rev发现并修复飞球落点被灰球覆盖的边界后通过。

- DEMO01倒数3秒可操作、可消除抵消；进入受击演出后居中大卡、暗背板、暂停提示，不可收起绕过。
- 公平暂停整个模拟比赛：双方输入、飞球、能量、压力和BOT都冻结；演出用独立现实时间继续播放，结束后恢复。
- 虚拟比赛钟冻结，不逐tick平移所有deadline。演出开始把到期incoming移到presentation，同刻多招共用最长演出，结束id校验仅结算一次。
- 动画结束后落灰；若接收方暂停前已有在途球，恢复后先结算该球再加已展示干扰，不能覆盖飞球落点，也不能在演出后额外抵消这包灰球。
- 基础动画原600–1000ms段0.4倍，1.5秒延长至2.1秒；风车1900–2600ms段0.45倍，黑洞5000–5550ms段0.4倍，巨猫2600–3050ms段0.45倍。其余段保持正常速度。
- 本地试玩新增‘试玩接招’：通过Mock内真实B充能+DUNK流程触发风车预告，便于重复体验；不接入LAN。
- 普通LAN房间仍默认cinematic=false，原有行为兼容；本次新规则只接本地DEMO01。

## 验证

- 11项cinematic测试先红后绿，涵盖局部单调连续映射、风车/黑洞/猫命中与结束时间、虚拟钟、3秒边界、双座输入拒绝、冻结飞球/压力/BOT、幂等结束、双招同刻、后台恢复不补发、真实-1.18落点覆盖回归与试玩接招。
- 5项展示设计测试、既有规则/网络客户端/节奏/动作回归，合计84通过；HTTP服务端另外4通过，共88。
- 独立设计页真实播放完整2.1秒，1.1秒处显示0.4倍翻腕段，结束切回恢复状态。设计页仍使用模拟数据，主DEMO01接入实际暂停逻辑。

浏览器最终实测：真实DEMO受击风车弹层rect (left430,top216,width420,height288)在1280×720视口正中；board与footer rect和预告前严格一致，aria-disabled=true且DUNK/充能/帮助禁用，暂停提示显示剩余秒数。演出结束data-cinema=none，空格可发射，shots从0到1；自然BOT也已继续蓄能反击。独立对照页播放1.1/2.1秒时已实际处于翻腕慢放，随后完整结束切到impact恢复。实战截图`/tmp/hoopire-live-centered-dunk.png`，慢放截图`/tmp/hoopire-centered-slow-dunk.png`。
