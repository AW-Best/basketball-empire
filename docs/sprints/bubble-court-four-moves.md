# DEMO01 四招选招试玩

状态：本地实现；不提交、不部署。

需求：四种动作接到单人模拟对战；能量满后选招；统一干扰数量，保留3秒预告和轻松节奏。

## 验收与设计

- /sm、/arch、/ui 预审通过；/rev 代码与设计复查通过。
- 100能量后点击 DUNK 打开四卡，点卡确认；取消不消耗。发送锁、回合号、能量、冷却、飞行与阶段均校验。
- 同一套100能量、清自身底排、最多4灰球、待落上限8、一次普通3球抵1规则；只有实际触底结束。
- 招式仅在 MockRoomStore 的 moveSelection 房间启用。普通 LAN 仍基础扣篮，不接受客户端自报时间/强度。
- 统一3秒预告；基础1.5s演出/0.8s命中，风车6s/4.4s，黑洞8s/6.2s，巨猫7s/4.5s。均从预告结束起算。保留原动作时长，长招防守窗口更长，当前是效果体验、尚非平衡版。
- 命中时由 reducer 落灰，飞行中延至本球结算。动画完成回调不参与伤害。
- 模拟对手真实消除蓄能、轮换4招；5s一发、扣后8s休息、35s压力不变。
- 最初演出占独立区域，后按用户要求改为固定棋盘上的叠加演出（见bubble-court-fixed-overlay.md）；可收起；双方待落分别显示来源、招式、剩余数量与秒数。最新动作占主镜头，重叠攻击不丢物理计时。
- Canvas纯函数，单一调度、≤30fps、DPR≤1.5；停止时不画，收起保留时间但停止画。失败回退基础并提示。

## 验证

- 新增测试先红后绿：四招数值、视觉命中点、取消/过期回合/飞行拒绝、LAN缺省、部分抵消后时钟、纯渲染、帧预算、减少动态效果、收起恢复。
- 相关既有规则、单人节奏、攻击循环、网络客户端/服务端回归测试。
- 浏览器390×844实际选招、取消保留100、3秒预告、对应Canvas无回退、演出中继续发射；棋盘与动画不重叠。

最终验证：15项四招专项通过；其余53项相关规则/节奏/攻击循环/客户端/帧预算通过，HTTP服务端4项在允许本机监听后通过，合计72项。浏览器390×844与390×650底部按钮在视口内、无水平溢出；风车/黑洞/巨猫Canvas均实际加载（fallback=false）。实测取消100能量保留、同局多次Dunk、演出时继续发射、双向待落来源、收起。所有变化仅本地。
